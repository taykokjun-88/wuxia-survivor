# 后端：账号 + 多角色 + 排行榜 + 反馈（Google 表格 + Apps Script）

```
朋友的浏览器 ──→ GitHub Pages（游戏，静态页面）
      │
      └──→ Apps Script 网页应用（Code.gs）──→ 这张 Google 表格
```

不需要服务器，不花钱。模式参照你的「知识岛」：玩家用 **PIN（加盐哈希）** 登录，会话用**令牌**，输错多次会**锁定**，注册要**邀请码**，后台就是这张表本身。

## 一、部署（约 10 分钟，只做一次）

1. **新建一张空白 Google 表格**，起个名字，比如「群侠千招后台」。
2. 菜单 **扩展程序 → Apps Script**，打开脚本编辑器。
3. 把编辑器里原有的代码全部删掉，粘贴本目录的 **`Code.gs`** 的全部内容。
4. 左侧 **项目设置（齿轮）→ 勾选「在编辑器中显示 appsscript.json 清单文件」**，回到编辑器，
   把 `appsscript.json` 的内容替换成本目录的 **`appsscript.json`**（时区、以及网页应用的访问设置）。
5. 在顶部函数下拉框选 **`setup`**，点 **运行**。第一次会要求授权：
   选你的账号 →「高级」→「转至…（不安全）」→ 允许。（脚本只访问这一张表。）
   运行成功后，表格里会多出 6 个标签页：`邀请 Invites`、`玩家 Players`（账号）、`角色 Characters`（每个账号最多 5 个角色，局外等级 / 天赋 / 装备都存这里）、`排行 Scores`、`日志 Logs`、`反馈 Feedback`。
6. **回到表格，刷新页面**，菜单栏会出现 **「武侠后台」**。点 **武侠后台 → 新建邀请码**，会依次问：名字、人数上限、昵称名单（可留空）、到期日期（可留空），然后弹出一个 6 位邀请码，**记下来发给朋友**。
7. 回到 Apps Script：右上角 **部署 → 新建部署 → 类型选「网页应用」**：
   - 执行身份：**我**
   - 谁可以访问：**任何人**
   - 点部署，复制得到的网址（以 `/exec` 结尾）。
8. **验证**：在浏览器里打开 `你的网址?action=ping`，应该看到 `{"ok":true,"v":1,...}`。
9. 打开游戏仓库的 **`data/config.json`**，把网址填进去：
   ```json
   { "api_url": "https://script.google.com/macros/s/xxxxxxxx/exec" }
   ```
   提交并推送到 `main`，GitHub Pages 会自动重新发布（见仓库根目录 README 的「在线玩」）。

之后朋友打开游戏链接，会看到登录/注册界面：填昵称、PIN、**你给的邀请码**才能注册。**没有游客模式**：没有账号就进不了游戏。

## 二、日常管理（都在表格里）

表格上方 **「武侠后台」** 菜单：

| 菜单 | 用途 |
|---|---|
| 初始化 / 修复表头 | 更新 `Code.gs` 后运行一次，补齐新增的列 |
| 新建邀请码 | 生成邀请码：名称、人数上限、昵称名单、到期日期 |
| 开启 / 关闭邀请码 | 输入邀请码即可切换；关闭后不能再用它注册，已注册的玩家不受影响 |
| 重设玩家 PIN | 朋友忘了 PIN：输入昵称和新 PIN，旧的登录会立即失效 |
| 封禁 / 解封玩家 | 封禁后不能登录、不出现在排行榜 |
| 清空排行榜（新赛季） | 清空成绩和最高记录，账号保留 |

也可以**直接改单元格**：
- `邀请 Invites`（和你知识岛的「班级」同一个思路，**每个邀请码就是一个"群"**）：

  | 列 | 作用 |
  |---|---|
  | 代码 Code | 6 位邀请码，注册时填写（不分大小写） |
  | 名称 Name | 群名，显示在玩家信息里，排行榜可以"仅看本群" |
  | 开放 Active | 改成 FALSE 就是关闭 |
  | 可用次数 MaxUses | 最多能注册几人，0 = 不限；「已用」自动累加 |
  | 昵称名单 Roster | **可选**，逗号 / 顿号 / 换行分隔。填了就**只有名单里的昵称**能用这个码注册（像知识岛的学号名单，可以给熟人预留昵称） |
  | 到期 Expires | **可选**。只填日期（如 2026-12-31）= 当天 23:59 前有效；填带时间的就精确到那一刻 |

  你可以同时有很多个邀请码（比如"篮球群""读书会"），玩家注册时用哪个码，就属于哪个群。
- `反馈 Feedback`：「状态」列自己改成"已处理"，并填处理时间（朋友的反馈、Bug、平衡意见都在这里）。
- `日志 Logs`：服务器和客户端的错误、登录失败过多等事件。
- `排行 Scores`：每一局的成绩明细（得分、用时、等级、击杀、构筑），可以用来看大家怎么玩。

## 三、修改了 Code.gs 之后

1. 粘贴新代码 → 运行一次 `setup`（补列）。
2. **部署 → 管理部署 → 编辑（铅笔）→ 版本选「新版本」→ 部署**。网址不变。
   （只保存不重新部署的话，线上用的还是旧版本。）

## 四、安全说明（请知晓）

- PIN 是 4–8 位数字，**强度有限**，防的是朋友之间的误操作和随手乱试：连续输错 5 次锁定 10 分钟；PIN 只以「盐 + SHA-256 哈希」形式存放，表里看不到明文。
- 网页应用的网址是公开的（任何知道网址的人都能发请求），所以**注册必须有邀请码**；不要把邀请码发到公开的地方，泄露了就在表里把它关掉。
- 成绩由游戏客户端上报，服务器只做合理性校验（用时、击杀速度、等级速度、通关时间、提交间隔），**决心作弊的人能绕过**。这是朋友之间的排行榜，不是比赛。
- 这张表里有昵称和密码哈希，**不要把表格公开分享**。
- Apps Script 有每日调用配额（个人账号很宽松，几个朋友玩用不完）。

## 五、接口（给开发者）

`POST <网址>`，请求体是 **`Content-Type: text/plain`** 的 JSON（这样浏览器不会发 CORS 预检，Apps Script 不支持预检）。
读取类用 `GET <网址>?action=...`。成功 `{"ok":true,...}`，失败 `{"ok":false,"err":"代码","msg":"中文提示"}`。

| action | 方式 | 说明 |
|---|---|---|
| `ping` | GET | 健康检查 |
| `board` | GET | `kind` = `score`/`speed`/`level`，可选 `map`（地图榜）`group`（本群）`char`（返回我这个角色的名次）；榜单按角色，显示角色名 |
| `register` | POST | `nick pin code` |
| `login` | POST | `nick pin`，返回新令牌 |
| `resume` | POST | `nick token`，用令牌自动登录并续期 |
| `logout` | POST | 令牌失效 |
| `submit` | POST | `nick token char won seconds level kills bosses map school starter qinggong enhance build difficulty version` |
| `createChar` / `deleteChar` / `getChar` | POST | 角色：创建（`name` `school`）/ 删除 / 读取某个角色的进度（`char` = 角色 id） |
| `saveState` | POST | 云存档（带 `char`）：流派 / 属性点 / 天赋（校验）/ 穿戴与丢弃装备 |
| `feedback` | POST | `type`（bug/balance/idea/other）`comment` |
| `log` | POST | 客户端日志（需登录） |

得分公式在 `Code.gs` 的 `computeScore`，游戏里 `scripts/score.gd` 有同一份，两边都用 `test/score_vectors.json` 校验，改的时候一起改。

## 六、测试

```bash
node backend/test/backend.test.js      # 34 个用例 × 2 种表格模式（见下）
```

测试在 Node 里用一个**模拟的 Google 环境**（`test/harness.js`）运行真正的 `Code.gs`。
每个用例跑两遍：理想表格，以及"自作聪明"的表格（把 ISO 时间字符串变成 Date、把纯数字字符串变成数字）——
真实的 Google 表格会这样做，比如昵称 `007` 会变成 `7`，所以昵称等列在 `setup` 里被设为纯文本。

`test/mock_server.js` 是一个本地假的 Apps Script 网页应用（302 重定向、不支持 CORS 预检），
用来对真实的游戏网页做端到端测试：`tests/e2e/run.sh`。


## 局外成长（修为 / 属性点）

- 提交成绩时，服务器按已校验的得分计算修为（`round(得分/80)` 封顶 400；通关 +40；首次通关再 +100）并累加到玩家的「修为 Exp」列，返回 `gained / exp / level / levelUp`。客户端不能直接上报修为。
- `saveState` 的 `state.alloc` 为五种属性点（pow/agi/vit/int/luk），服务器校验：每项 0–99 的整数、总和不超过 `3 × (等级 − 1)`；与已有存档合并。
- 升级到新版 Code.gs 后，请在表格里运行一次 `setup`（菜单「初始化 / 修复表头」）：会补齐新增的列和「角色 Characters」表。**旧账号的进度（流派 / 修为 / 天赋 / 装备）会在第一次登录时自动迁移成第一个角色**（角色名 = 昵称）。
